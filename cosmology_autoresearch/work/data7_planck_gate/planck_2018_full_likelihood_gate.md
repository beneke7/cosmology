# Planck 2018 full-likelihood access and run-feasibility gate

Checked 2026-09-25 03:13 UTC. This is a read-only gate: no Planck likelihood file was downloaded, no package installed, and no model or likelihood was run.

## Verdict

The paper's `plikTTTEEE+lowl+lowE` label maps cleanly to the public Planck PR3 baseline likelihood data: full high-\(\ell\) Plik HM TT+TE+EE, Commander low-\(\ell\) TT, and SimAll low-\(\ell\) EE. It is **not** Plik-lite, and the named three-part combination does **not** include the separate lensing likelihood. The original data archive is publicly retrievable; an unauthenticated HTTP `HEAD` to its official PLA product endpoint returned 200. The ESA metadata page assigns archived data the CC BY-NC 3.0 IGO terms. No Planck-collaboration account is indicated as required; the archive's browser basket/email-link flow is a user-interface step, not a collaboration-only entitlement.

An exact, project-local **standard CAMB + full Planck ΛCDM validation is feasible in principle**, but not runnable in the current environment without installing missing Python dependencies and staging the Planck data. The current Linux x86-64/Python 3.12.3 environment matches the official CAMB 2.0.4 wheel; standard CAMB through that wheel needs no Fortran compiler. There are 286 GB free, but the likelihood-data archive's exact byte size was not published in the checked ESA metadata and the transfer is chunked, so I do not invent a size. Cobaya's install documentation warns that cosmology package installs may require several GB.

An **independent IVS source implementation is not ready to run here**: no Fortran compiler is on `PATH`, the local pinned CAMB source archive omits the `forutils` git submodule, and a precompiled CAMB wheel cannot be patched. A faithful reproduction of the paper's result is additionally blocked by missing authors' modified-CAMB provenance, full Cobaya configuration, and scalar perturbation initial-condition prescription, as already recorded in the local author-artifact audit.

## Exact product mapping and paper ambiguity

The target's arXiv v1 methods section (local PDF SHA-256 `0ca9dfa076a493eda6b4ab8fd7e5535ed410aa4d2e74f70442d835dd8d262a0c`) says `plikTTTEEE+lowl+lowE`, calls these Planck 2018 data, and describes temperature and E-mode spectra at low and high multipoles. In the official Cobaya 3.6.2 component definitions, the corresponding exact data files and aliases are:

| Paper term | Cobaya component (v3.6.2) | Exact PR3 `.clik` product | Meaning |
|---|---|---|---|
| `plikTTTEEE` | `planck_2018_highl_plik.TTTEEE` | `plik_rd12_HM_v22b_TTTEEE.clik` | Full Plik half-mission high-\(\ell\) TT+TE+EE; includes nuisance parameters. Not the nuisance-marginalized `TTTEEE_lite` product. |
| `lowl` | `planck_2018_lowl.TT_clik` | `commander_dx12_v3_2_29.clik` | Commander low-\(\ell\) TT. |
| `lowE` | `planck_2018_lowl.EE_clik` | `simall_100x143_offlike5_EE_Aplanck_B.clik` | SimAll low-\(\ell\) EE. |

The filenames are under `baseline/plc_3.0/hi_l/plik/` and `baseline/plc_3.0/low_l/{commander,simall}/`. The exact data artifact is `COM_Likelihood_Data-baseline_R3.00.tar.gz`; ESA also lists the original likelihood-code bundle `COM_Likelihood_Code-v3.0_R3.01.tar.gz`. Current Cobaya implements the `clik` interface with the pure-Python `clipy` package, so that documented route needs the PR3 likelihood **data** plus `clipy`; it does not require compiling the original `clik` package. The paper does not identify these archive filenames/release versions, its Cobaya aliases, or whether it used this implementation or the older original `clik` code.

Current Cobaya adds component nuisance parameters automatically. Its v3.6.2 full-Plik YAML pulls calibration/temperature/polarization/foreground nuisance defaults and its SZ prior. The paper's Table I gives broad cosmological-parameter priors but does not state the Planck nuisance parameters/priors or provide a run YAML. Thus the dataset shorthand is identifiable; the complete nuisance/configuration contract is not. Do not silently add lensing: `planck_2018_lensing.clik` is a fourth, separate component and is not named. Likewise, LAMBDA's 63 MB `CosmoParams_base-plikHM-TTTEEE-lowl-lowE_R3.00` item is a precomputed parameter-chain product, not the raw likelihood; the 11 GB full-grid product is also not a substitute for running the full likelihood.

## Availability, sizes, versions, requirements, and terms

- **Public data/access:** ESA says the PLA contains public Planck products; the PR3 Cosmology product page exposes the baseline data and code archive names. The official `product-action` endpoint returned HTTP 200 without cookies and had `Transfer-Encoding: chunked` but no `Content-Length`, so compressed size is unknown here. No bytes were fetched. The ESA archive states data hosted there are CC BY-NC 3.0 IGO. Use the archive's citation/attribution guidance and preserve the non-commercial restriction; the original code archive's own embedded terms have not been inspected.
- **LAMBDA cross-check:** NASA/IPAC's PR3 ancillary-data page confirms the public product family and labels the 63 MB and 11 GB items as chains/full-grid results. These must not be treated as the full likelihood data. The primary full-likelihood path documented by Cobaya is the ESA PLA baseline archive.
- **Cobaya:** audited release 3.6.2, Python `>=3.10`; PyPI wheel 494,975 B, SHA-256 `5e81da5900442c1a20a0ffa9c1ff212983106a7473b29555cecc2af3e4214da0`. Runtime requirements include NumPy, SciPy, pandas, PyYAML, requests, py-bobyqa, GetDist, rapidfuzz, packaging, tqdm, portalocker, dill, and typing_extensions. Cobaya code is LGPL-3.0-or-later with the additional conditions stated in its license (arXiv timing for publications and prompt confirmed bug reporting); documentation is GFDL.
- **Planck wrapper:** Cobaya's current docs use `clipy` and specify `pip install clipy-like` (the similarly named `clipy` PyPI project is unrelated). PyPI `clipy-like==0.15` wheel 41,355 B, SHA-256 `9bf56a1c648cab345e9fcb7f83c9a79cd82f92e4f6fe4392900eec23b96f49d0`; Python `>=3.9`, NumPy `>=1.23.5`, Astropy `>=2.0`; JAX is optional. The official CobayaSampler source README reports repository tag v0.16 (July 2026), while PyPI metadata checked here exposes 0.15, so pin a specific source/tag or PyPI artifact instead of the moving word “latest.” Source license is MIT.
- **CAMB:** audited `camb==2.0.4`, Python `>=3.10`; the official wheel matching local x86-64 Linux/glibc 2.39 is 2,393,435 B, SHA-256 `9b7e6558b2049757e96496b8a33461d8ff11acd79017cfbd00a573dbc8d1e366`. Local source tar: 15,959,613 B, SHA-256 `66808001e908982857c312cc84671c66a51312251a7b15e07507d66b4788c0c7`, pinned CAMB commit `a6de8cc59124c8bbe3924f1c546f96cef73dcabb`; `forutils` contents/gitlink SHA are absent. CAMB's local license is LGPL-3.0-or-later with the same arXiv and bug-report conditions and a notice-retention requirement. A normal wheel install is compiler-free; edited-source IVS is not.
- **Current workspace:** `.venv` uses Python 3.12.3 with NumPy 2.5.3 and SciPy 1.18.1. Cobaya, CAMB, `clipy-like`, Astropy, pandas, PyYAML, requests, py-bobyqa, GetDist, rapidfuzz, tqdm, portalocker, and dill are not installed. No Planck likelihood package/data is present.
